Installation

Use Python 3.12. Windows CPU is tested locally; Linux CPU is checked by CI. CUDA/TPU acceleration is not claimed as tested by this release. The package uses JAX/jaxlib 0.4.38 and NumPy 1.26.4 to preserve the original numerical runtime.

git clone https://github.com/hl682/Crucibles_JAXMARL.git
cd Crucibles_JAXMARL
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS:
source .venv/bin/activate
python -m pip install -e .
crucibles smoke --game 225
crucibles play --game 225

For a fresh checkout, start.cmd on Windows or bash start.sh on Linux creates a local virtual environment, installs the package and runs the server. First installation requires network access. After installation, crucibles play --game 225 is the single launch command; gameplay does not require network access.

Connection refused: check the running process

The terminal must remain open while you play. Wait for Crucibles JAXMARL ready, then open the exact printed HTTP address. Opening the saved HTML as file:// does not start Python.

crucibles play --game 225 --port 8765
# Separate terminal, with the server still running:
python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8765/health').read().decode())"

If port 8765 belongs to another process, the launcher reports that failure. Choose --port 8766 and use its printed address. The launcher does not terminate other services. Ctrl+C stops your server. Stopping or restarting it ends active in-memory sessions; their logs remain on disk.

Solo, mixed teams and local multiplayer

  1. Choose a game and an integer seed, then create a session. First JAX compilation may take a minute.
  2. Assign any role IDs to Host, including ranges such as 0,2,5-8. Assign all roles to control the entire team. Each role retains its original action and observation row.
  3. Queue a legal command for each controlled role, then advance the joint step. All commands enter the same original JAX transition. Unqueued roles use the disclosed untrained uniform-legal AI.
  4. Create a player invitation and open it in a second browser tab or another browser on this computer. Assign roles to that participant. Each participant sees only their assigned role views and can submit only their owned actions; the Host controls the joint clock.
  5. Reassign roles at any time before the next joint step. Assign them to AI to release control. The world, seed and accumulated returns continue without reset.

The service binds to loopback for local multiplayer. Networked multiplayer across separate computers is not provided by this release. There is no game-specific cap on the number of controlled agents. Four simultaneous sessions bound local compilation memory; closing a session releases it while preserving logs.

Keyboard and cameras

Select a controlled role camera. Arrow keys or WASD queue the matching native directional action when that game declares a MOVE/WALK command. Use each role's legal-command selector for game-specific interactions, communication and commitments. Space advances one joint step. Form controls keep their normal keyboard behavior. The AI clock advances at the selected interval and may be paused.

Role views use the manifest's entity and map visibility. Full-state debug requires Host permission, carries a visible label and permanently marks that session's information condition as debug-exposed. Debug observation is unsuitable as a blind human benchmark. Legacy abstract games have no spatial geometry; their renderer shows actual native observation values without inventing a map.

Benchmark and takeover records

Each session writes local-runs/<session-id>/events.jsonl. The hash chain records source and manifest hashes, package version, seed, all joint actions and rewards, participants supplying inputs, AI-controlled roles, exact PRNG schedule, role transfers and debug exposure. Terminal sessions write benchmark.json with per-role returns and the whole-session control history classification.

Engineering tests explicitly set --engineering. The server records input provenance but cannot independently verify that inputs came from a human. Consequently human_scores stays null and no public human leaderboard is fabricated. Mixed input, pure AI and all-human-input histories remain distinct; returns are never assigned only to the final controller or summed across unrelated games.

Keep invitation and Host capability URLs private. They are used only within the running service and are excluded from log records. Refreshing with the same fragment reconnects to the same session while the server remains running. Session world state is not checkpointed for restart.
