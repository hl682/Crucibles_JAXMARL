# GI092 · Lumen Locks: Cross-Wired Signals

Deliver both physical cargo objects from the east loading bay to the northern goal, using two cross-wired remote gate operators and brief binary broadcasts.

## Identity and original contract

3 independently actionable roles; 10 discrete commands per role; 154 native observation columns per role; original horizon 128 steps. Declared per-step reward range: -1 to 1. Observation regime: `partially_observable`.

## Objective and gameplay

Deliver both physical cargo objects from the east loading bay to the northern goal, using two cross-wired remote gate operators and brief binary broadcasts.

Sensor 0's bit is required at role 1's panel; sensor 1's bit is required at role 0's panel. Only local owners can directly read a sensor. A correct remote pulse opens the corresponding courier gate for six steps; a wrong pulse closes it and jams its operator. Binary messages change what other roles observe for four frames.

- Role 0 reads sensor 0 only nearby, but its panel needs sensor 1's bit. Role 1 reads sensor 1 nearby, but its panel needs sensor 0's bit.

- Walls separate both operators and the courier. Operators can move, read, send and pulse; only the courier can carry cargo.

- Broadcast bit 0 or 1 for four steps; sending has a three-step cooldown and replaces movement for that turn.

- A correct panel pulse costs one energy and opens its distant gate for six steps. Wrong pulses close it and jam the panel for two steps.

- Delivering cargo redraws both clues, clears broadcasts and closes gates. Deliver both cargo objects before step 128.

Ending: All two cargo objects delivered ends naturally. Each delivery gives every role +0.5 and the final delivery adds +0.5. Otherwise truncate at step 128. Deliveries redraw both private sensor bits and close both gates.

## What this game explores

Information, sensing & communication: Who knows a fact, when it was measured, and whether it was communicated are separate state variables. Test memory or communication using only the same role-visible evidence.

Complementary production & service: A useful outcome requires ordered stages, scarce equipment or another role's capability. Measure real completed products and resource circulation rather than counting intermediate actions as success.

Joint transport & shared access: Positions, load geometry, occupancy and persistent access constrain whose action can succeed next. Distinguish physical handoff, shared controls and simultaneous force from a cosmetic cooperation label.

These are questions supported by rule structure, not observed learning effects.

For every owned role choose a legal command and press `Queue`. Arrow keys / WASD queue a declared directional action for the current role camera when available. Space or `Advance one joint step` advances everyone together. Non-directional games use the selectors.

## Reinforcement-learning integration

```python
import jax
from crucibles_jaxmarl import make

env = make("gi092")
key = jax.random.PRNGKey(0)
key, rk, ak, sk = jax.random.split(key, 4)
obs, state = jax.jit(env.reset)(rk)
actions = env.sample_actions(ak, state)
obs, state, rewards, dones, info = jax.jit(env.step_env)(sk, state, actions)
done = dones["__all__"]
```

Observations are float32 vectors of width 154; actions are scalar int32; masks have 10 entries. Supply all 3 roles each transition. Masked sampling is an engineering reference, not a trained learner.

`step_env` retains terminal data without reset. `step` performs outer autoreset and keeps terminal data in `info["raw_state"]` and `info["raw_observation"]`. Use `dones["__all__"]` for episode boundaries; separate completion, failure and time limit in analysis.

JIT or vmap equal identities and shapes. Split independent reset, policy and transition keys. Group different shapes explicitly; do not shrink the population or horizon. Host rendering stays outside training.
