## Objective and gameplay

Construct traversable patterned paths and physically reach and commission a socket. Private destination preferences and shared claim bonuses shape which paths actors favor.

Every placed tile imposes equality constraints on neighboring edge bits. Rotation consumes pins and can change a peer's next placement mask or movement route. Inventory is finite, placements permanent, handoffs preserve tile identity and orientation.

- Carry one of nine conserved tiles. The courtyard void becomes traversable only where real tiles are installed.

- Place into the faced empty courtyard cell only when every existing neighbor has an equal facing edge bit.

- Movement uses open outgoing and incoming ports. Matching closed edges allow adjacency but block crossing.

- Placements are permanent. Each clockwise rotation spends a pin; placed tiles cannot rotate under an occupant or violate neighbors.

- A builder can turn, pass a tile to a waiting empty peer, or return it to the depot with its orientation preserved.

- Cyclic actor priority rechecks simultaneous construction against the newly updated board.

- Commission a socket only while physically standing there. Private socket preference remains role-only.

- Tile identity, orientation, N/E/S/W ports and ownership are actual state attributes. Recorded replay and animation remain unexecuted.

Ending: Every builder has commissioned one socket; no puzzle solver or construction score decides completion.

## What this game explores

Information, sensing & communication: Who knows a fact, when it was measured, and whether it was communicated are separate state variables. Test memory or communication using only the same role-visible evidence.

Joint transport & shared access: Positions, load geometry, occupancy and persistent access constrain whose action can succeed next. Distinguish physical handoff, shared controls and simultaneous force from a cosmetic cooperation label.

These are questions supported by rule structure, not observed learning effects.

## Reinforcement-learning integration

```python
import jax
from crucibles_jaxmarl import make

env = make("gi185")
key = jax.random.PRNGKey(0)
key, rk, ak, sk = jax.random.split(key, 4)
obs, state = jax.jit(env.reset)(rk)
actions = env.sample_actions(ak, state)
obs, state, rewards, dones, info = jax.jit(env.step_env)(sk, state, actions)
done = dones["__all__"]
```

Observations are float32 vectors of width 157; actions are scalar int32; masks have 12 entries. Supply all 3 roles each transition. Masked sampling is an engineering reference, not a trained learner.

`step_env` retains terminal data without reset. `step` performs outer autoreset and keeps terminal data in `info["raw_state"]` and `info["raw_observation"]`. Use `dones["__all__"]` for episode boundaries; separate completion, failure and time limit in analysis.

JIT or vmap equal identities and shapes. Split independent reset, policy and transition keys. Group different shapes explicitly; do not shrink the population or horizon. Host rendering stays outside training.
