## Objective and gameplay

Deliver each worker's personal cargo to its exact opposite-bank flag, while maintaining shared crossing structures.

Both ends of a placed beam need a pin or a worker holding that exact endpoint on this tick. With any temporary end the beam carries one river occupant; with both ends pinned it carries two. Unsupported or overloaded occupied beams break, and workers on unsafe river cells return home. Holdings prevent movement that turn; pins and beams have unique persistent custody.

- Each role carries personal cargo to its opposite-bank flag. Cargo delivery is automatic at that exact cell.

- Pick and place one beam per worker. Horizontal and vertical orientation changes the actual three-cell coverage and endpoint positions.

- Both beam ends need installed pins or workers choosing Hold/Brace at the exact endpoint. A temporary bridge supports one river occupant; two pins support two.

- New unsupported river entries are blocked. Releasing an occupied bridge or overloading it breaks the beam and returns exposed workers, with carried materials, home.

- Bank cells allow co-location. Resources resolve in rotating role order. Installed pins stay attached even after a beam breaks.

- All state used in the scene is public. Only an independent real replay can establish whether a proposed construction script works.

Ending: All three cargo deliveries are recorded, or all three beams are broken. Otherwise truncate at 96 nonterminal steps.

## What this game explores

Complementary production & service: A useful outcome requires ordered stages, scarce equipment or another role's capability. Measure real completed products and resource circulation rather than counting intermediate actions as success.

Joint transport & shared access: Positions, load geometry, occupancy and persistent access constrain whose action can succeed next. Distinguish physical handoff, shared controls and simultaneous force from a cosmetic cooperation label.

Team opposition & interception: Cooperation within a team can coexist with opposition between teams. Preserve team membership, capture and possession rules, and report each team's outcomes instead of assuming a single shared return.

These are questions supported by rule structure, not observed learning effects.

## Reinforcement-learning integration

```python
import jax
from crucibles_jaxmarl import make

env = make("gi126")
key = jax.random.PRNGKey(0)
key, rk, ak, sk = jax.random.split(key, 4)
obs, state = jax.jit(env.reset)(rk)
actions = env.sample_actions(ak, state)
obs, state, rewards, dones, info = jax.jit(env.step_env)(sk, state, actions)
done = dones["__all__"]
```

Observations are float32 vectors of width 96; actions are scalar int32; masks have 13 entries. Supply all 3 roles each transition. Masked sampling is an engineering reference, not a trained learner.

`step_env` retains terminal data without reset. `step` performs outer autoreset and keeps terminal data in `info["raw_state"]` and `info["raw_observation"]`. Use `dones["__all__"]` for episode boundaries; separate completion, failure and time limit in analysis.

JIT or vmap equal identities and shapes. Split independent reset, policy and transition keys. Group different shapes explicitly; do not shrink the population or horizon. Host rendering stays outside training.
