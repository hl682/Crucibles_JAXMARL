## Objective and gameplay

Transport four complementary parcels to their bilateral private target depots by negotiating scarce expiring bridge access; choose toll revenue, prompt passage and reciprocal delivery assistance.

Each issuer must use the other bridge to cross; neither can issue itself a permit. A grant escrows a scarce real token and an action near a control point. Permits constrain entering the only river crossings. Toll quotes, expiry, physical congestion and complementary recipient rewards create cross-agent opportunities and costs.

- North issuer is agent 0; south issuer is agent 1. Issuers cannot request their own bridge.

- Requests are posted from a bridge approach, lock the old advertised toll, last four ticks and become grantable next tick.

- At a nearby control point, an issuer can bond one token to grant a six-tick permit to a pending requester.

- Entering a bridge consumes that permit, charges its quote and refunds the issuer bond. Unused expiry also refunds the bond.

- The sum of all wallets and bridge bonds stays eight; changing a posted toll cannot change an existing quote.

- A carrier already on a bridge may exit even if its permit is gone; backing out does not refund a used toll.

- Each parcel has a distinct recipient; its private target row is sampled from the supplied reset key and revealed to sender, recipient and carrier.

- Only adjacent empty carriers accept hand-offs; parcel identity and recipient persist.

- Delivery rewards carrier +0.5, sender +0.25 and recipient +1; toll utility is a zero-sum 0.05 per token; every live step costs 0.001.

- All four deliveries end naturally; otherwise the horizon is 160.

Ending: Terminate when all four unique parcels have been delivered. Otherwise truncate at 160; undelivered demands remain explicitly unsatisfied.

## What this game explores

Information, sensing & communication: Who knows a fact, when it was measured, and whether it was communicated are separate state variables. Test memory or communication using only the same role-visible evidence.

Commitment, exchange & governance: Promises consume time, liquidity, access or material. Separate an announced agreement from a binding commitment and from its eventual delivery; log cancellation and expiry too.

Joint transport & shared access: Positions, load geometry, occupancy and persistent access constrain whose action can succeed next. Distinguish physical handoff, shared controls and simultaneous force from a cosmetic cooperation label.

These are questions supported by rule structure, not observed learning effects.

## Reinforcement-learning integration

```python
import jax
from crucibles_jaxmarl import make

env = make("gi153")
key = jax.random.PRNGKey(0)
key, rk, ak, sk = jax.random.split(key, 4)
obs, state = jax.jit(env.reset)(rk)
actions = env.sample_actions(ak, state)
obs, state, rewards, dones, info = jax.jit(env.step_env)(sk, state, actions)
done = dones["__all__"]
```

Observations are float32 vectors of width 182; actions are scalar int32; masks have 14 entries. Supply all 4 roles each transition. Masked sampling is an engineering reference, not a trained learner.

`step_env` retains terminal data without reset. `step` performs outer autoreset and keeps terminal data in `info["raw_state"]` and `info["raw_observation"]`. Use `dones["__all__"]` for episode boundaries; separate completion, failure and time limit in analysis.

JIT or vmap equal identities and shapes. Split independent reset, policy and transition keys. Group different shapes explicitly; do not shrink the population or horizon. Host rendering stays outside training.
