## Objective and gameplay

Each steward deposits six fruits at their own storehouse while preserving or restoring the shared orchard network; fruit can instead be invested or gifted.

Agents compete for local fruit, spend their own potential income on root/soil restoration, propagate moisture and seed support to neighbouring patches on delayed four-step pulses, and can transfer fruit only to willing adjacent receivers.

- Three moving stewards each seek six fruits in their own storehouse; carried fruit can instead fund planting or be gifted.

- Harvest one fruit from the nearest adjacent living patch. Taking its last fruit damages one root.

- Plant spends one carried fruit to restore one root, one fruit and one moisture, within capacities.

- Water a rooted patch using one carried water; refill a two-unit bag beside the central spring.

- Every four ticks, moist living patches regenerate using retained fruit or a nearby seed-rich patch.

- A moisture-three patch sends moisture to nearby patches on a pulse. This incoming moisture can support their growth only on a later pulse.

- Give plus an adjacent partner receive action transfers one fruit. Store deposits pay only the depositing role.

- Patch and gift contests rotate first-mover priority by the clock; simultaneous collision rules prevent overlapping bodies.

- All stores at six ends with a shared +2 bonus. Complete loss of roots and planting fruit ends with -2. Otherwise step 128 truncates.

- The scene and policy both see the actual public map, positions, inventories, ecological levels and event flags.

Ending: Success when all stores reach six; collapse when every root is zero and every carried fruit is zero without success. Otherwise horizon 128 truncates. An ecologically stranded state not matching collapse can persist to the horizon.

## What this game explores

Resource commons & externalities: An action changes a persistent resource or burden that another role also encounters. Compare extraction with maintenance and record the downstream resource trajectory.

These are questions supported by rule structure, not observed learning effects.

## Play it: operating walkthrough

```sh
crucibles play --game gi104
```

Keep Python running and open its printed address. Select this game, set a seed and press `Create session`. The game itself is always English.

Assign a role range to Host with `Assign / take over`, or `Assign all roles`. Invite a second participant with `Create player invitation`, then assign a disjoint subset. Every original role is available.

For every owned role choose a legal command and press `Queue`. Arrow keys / WASD queue a declared directional action for the current role camera when available. Space or `Advance one joint step` advances everyone together. Non-directional games use the selectors.

Unqueued roles use the labelled untrained uniform-legal policy. Take over or release roles before the next step without resetting. Full-state debug is privileged and permanently logged; role cameras preserve permissions. Close the session to retain logs. Server restart does not restore sessions.

## Reinforcement-learning integration

```python
import jax
from crucibles_jaxmarl import make

env = make("gi104")
key = jax.random.PRNGKey(0)
key, rk, ak, sk = jax.random.split(key, 4)
obs, state = jax.jit(env.reset)(rk)
actions = env.sample_actions(ak, state)
obs, state, rewards, dones, info = jax.jit(env.step_env)(sk, state, actions)
done = dones["__all__"]
```

Observations are float32 vectors of width 164; actions are scalar int32; masks have 12 entries. Supply all 3 roles each transition. Masked sampling is an engineering reference, not a trained learner.

`step_env` retains terminal data without reset. `step` performs outer autoreset and keeps terminal data in `info["raw_state"]` and `info["raw_observation"]`. Use `dones["__all__"]` for episode boundaries; separate completion, failure and time limit in analysis.

JIT or vmap equal identities and shapes. Split independent reset, policy and transition keys. Group different shapes explicitly; do not shrink the population or horizon. Host rendering stays outside training.
