Original array kernels are wrapped with agent-keyed observations, actions, rewards and done dictionaries. The API follows the JaxMARL convention without modifying or registering into the upstream project.

Reset and one transition

import jax
from crucibles_jaxmarl import make, registered_envs

env = make("gi072")  # integers and game-v3-00072 also work
key = jax.random.PRNGKey(0)
key, reset_key, action_key, step_key = jax.random.split(key, 4)
obs, state = env.reset(reset_key)
actions = env.sample_actions(action_key, state)  # legal sampling
obs, state, rewards, dones, info = env.step_env(step_key, state, actions)
assert set(obs) == set(env.agents)
done = dones["__all__"]

Every agent supplies a command simultaneously. Actions are scalar int32 and masks have shape (num_actions,) for each role. The original kernel controls masked-command behavior, ordering, contention, per-agent rewards and terminal conditions. The interactive server rejects illegal inputs before invoking the kernel.

Terminal semantics

step_env returns original terminal observations and state without resetting. step splits the supplied key into transition and reset keys and performs terminal-triggered outer autoreset. It retains terminal data as info['raw_state'] and info['raw_observation']. An optional reset_state supplies the autoreset state. Spatial kernels declare raw absorbing terminals; early abstract kernels retain their original historical behavior, which is separately documented.

obs, state, rewards, dones, info = env.step(key, state, actions)
# Observe the terminal state even when state has been reset:
terminal_state = info["raw_state"]

JIT, batches and scans

reset = jax.jit(env.reset)
step = jax.jit(env.step)
batch_keys = jax.random.split(key, 16)
batch_obs, batch_state = jax.jit(jax.vmap(env.reset))(batch_keys)
batch_actions = jax.vmap(env.sample_actions)(batch_keys, batch_state)
batch_obs, batch_state, r, d, info = jax.jit(jax.vmap(env.step))(
    batch_keys, batch_state, batch_actions)

def rollout(carry, _):
    key, state = carry
    key, ak, sk = jax.random.split(key, 3)
    actions = env.sample_actions(ak, state)
    obs, state, rewards, dones, info = env.step(sk, state, actions)
    return (key, state), (rewards, dones)

(_, final_state), trajectory = jax.jit(
    lambda k, s: jax.lax.scan(rollout, (k, s), None, length=128)
)(key, state)

Batch and horizon sizes above are usage examples, not substitutions for a game's original verification horizon. Batch the same environment identity and shape with vmap. Different game shapes require grouping or an explicit padded learner; the library does not silently shrink maps, agent populations or observations. The pure state tree and explicit keys support recurrent, context-conditioned and meta-RL pipelines; no DiscoRL compatibility, differentiability of discrete game dynamics, convergence or transfer result is claimed.

Training never consumes the browser render projection. Render callbacks use host-side NumPy/Pillow and are deliberately outside the JAX-compiled training path. Installation verifies source and manifest hashes before loading a kernel. Game modules depend only on the bundled source and their installed numerical dependencies.

Upstream reference

The facade follows the official JaxMARL MultiAgentEnv API. Installation and documentation organization were reviewed against JaxMARL and its documentation. This independent library is not an upstream certification or benchmark result.
